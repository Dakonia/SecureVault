# 11 · Развёртывание сервера (runbook)

Здесь фиксируется, **что ставим на сервер и как**. Обновляется по мере работы.

## Что вообще ставится на сервер
Только наша «серверная часть» — программа-приёмник (receiver). Она:
- принимает зашифрованные «коробки» (шифротекст) от клиентов,
- проверяет пропуск (пока токен, потом mTLS-сертификаты),
- складывает коробки как есть — **не открывая**,
- отдаёт коробки по запросу.

Всё это работает **в Docker-контейнере** — изолированно от остального сервера. Чужие данные и твой VPN не затрагиваются.

## Из чего состоит пакет (`server/`)
| Файл | Что это |
|---|---|
| `main.go` | сам приёмник (язык Go): три команды — `/health`, `POST /blobs` (сохранить коробку), `GET /blobs/{id}` (забрать). Ничего не расшифровывает. |
| `Dockerfile` | как собрать крошечный образ (статический бинарник, без лишнего). |
| `docker-compose.yml` | как запустить: слушает только `127.0.0.1:8088` (наружу НЕ смотрит), данные в томе `sv-data`. |
| `.env` | секретный токен доступа (генерируется автоматически, в git не попадает). |
| `install.sh` | ставит Docker (если нет), генерирует токен, собирает и запускает. |

## Почему Go и Docker
- **Docker** — изоляция (не заденет VPN/чужое), запуск одной командой, и **работает на Linux и на Windows** (под будущий сервер компании).
- **Go** — лёгкий (важно на слабом VPS 1 ГБ), быстрый, компилируется в один файл, кроссплатформенный (в т.ч. под Windows).

## Безопасность на старте (и что усилим потом)
- Сервис слушает **только локально** (`127.0.0.1:8088`) — из интернета его нет. Для теста доступ через SSH-туннель.
- Доступ по **токену** (Bearer). ⚠️ Это временно — заменим на **mTLS** (сертификат устройства).
- Данные в томе — это уже шифротекст (клиент шифрует до отправки). Сервер видит только «мусор».
- Дальше (на отдельном чистом сервере): WireGuard + SPA + nftables (невидимость), LUKS (шифрование диска).

## Развёртывание (Linux, Debian/Ubuntu)
```bash
# на сервере, в папке server/
sudo bash install.sh
# проверка:
curl -fsS http://127.0.0.1:8088/health   # -> ok
```

## Тест «сервер слеп» (round-trip)
1. На клиенте шифруем файл (age) и отправляем: `POST /blobs` → получаем id.
2. На сервере смотрим сохранённый файл — это нечитаемый шифротекст.
3. Забираем `GET /blobs/{id}`, расшифровываем на клиенте — данные целы.
4. Вывод: по сети прошёл только шифротекст, сервер содержимого не видел.

## Про будущий сервер компании (возможно Windows)
- Ядро (этот Docker-пакет) переносится на Windows с Docker Desktop без изменений.
- Отличается только «обвязка невидимости»: на Windows — WireGuard-for-Windows + Windows Firewall вместо nftables. Опишем отдельно, когда дойдём.
