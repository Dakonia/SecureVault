# 07 · План реализации

Порядок работ. Сроки ориентировочные, зависят от загрузки.

## Этап 0 · Решения до старта
- [ ] Зафиксировать приоритет: юридическая чистота (РФ, ФЗ-152) vs анонимность. Влияет на выбор сервера.
- [ ] Подтвердить: сервер физический, у нас. ✔ (решено)
- [ ] Определить бюджет на ключи: сколько YubiKey (минимум 3 для полного доступа), остальным — YubiKey или флешки.
- [ ] Выбрать: строгий zero-knowledge на старте (аналитика на клиенте) — да/нет.

## Этап 1 · Криптоядро (прототип) — 1–2 недели
- [ ] Мини-прототип: зашифровать данные под несколько получателей (age + конверты).
- [ ] Привязать расшифровку к YubiKey (`age-plugin-yubikey`).
- [ ] Реализовать Shamir «2 из 3» для мастер-секрета.
- [ ] Проверить: без нужного ключа данные не открываются.

## Этап 2 · Сеть и сервер — 1–2 недели
- [ ] Установить сервер с LUKS2 + dropbear-initramfs (удалённый unlock).
- [ ] Поднять WireGuard (сервер + тестовый клиент).
- [ ] Настроить nftables (default-drop) + fwknop (SPA).
- [ ] Настроить mTLS (CA, клиентские сертификаты).
- [ ] Проверить: снаружи сервер «не отвечает», доступ только через WireGuard+SPA.

## Этап 3 · Клиентское приложение — 2–3 недели
- [ ] Tauri-приложение, нейтральное имя/иконка.
- [ ] Вход по ключу (YubiKey/флешка) + PIN.
- [ ] Формы: загрузка файлов, ввод цифр/отчётов.
- [ ] Клиентское шифрование при отправке (интеграция криптоядра).
- [ ] Никаких открытых данных/истории на диске.

## Этап 4 · Сервер-хранилище и API — 1–2 недели
- [ ] API (Rust axum / Go): приём и выдача шифротекста, проверка mTLS.

- [ ] Убедиться: сервер оперирует только blob'ами, ничего не расшифровывает.

## Этап 5 · Роли, доступ, журнал — 1–2 недели

- [ ] Audit-log (append-only, hash-chain).

## Этап 7 · Аналитика — по мере необходимости
