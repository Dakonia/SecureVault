# 03 · Шифрование и ключи

## Конвертное шифрование (envelope encryption)

Схема, при которой сервер никогда не видит открытых данных.

```
Данные отчёта
   │
   │  шифруем случайным ключом DEK (XChaCha20-Poly1305)
   ▼
Шифротекст ──────────────────────────────► на сервер (blob)

DEK (32 байта)
   │  кладём в "конверты" под публичные ключи получателей
   ├── конверт для Директора №7   (его X25519 pubkey)
   ├── конверт для Полного доступа 1
   ├── конверт для Полного доступа 2
   └── конверт для Полного доступа 3
        │
        ▼
   конверты ─────────────────────────────► на сервер (blob)
```

- **DEK** (Data Encryption Key) — свой на каждую запись/файл. Шифрует сами данные.
- **Конверт** — DEK, зашифрованный под публичный ключ конкретного получателя. Открыть конверт может только владелец приватного ключа.
- Добавить получателя = добавить конверт. Убрать = удалить конверт (плюс сменить DEK для будущих данных).

### Почему так
- Сервер хранит шифротекст + конверты — всё непрозрачно.
- Один и тот же DEK не надо передавать: каждый получатель достаёт его сам из своего конверта.
- Изоляция директоров — автоматически: нет конверта → нет DEK → нет данных.

## Где живут приватные ключи

| Роль | Носитель ключа | Как расшифровывает |
|---|---|---|
| Директор (YubiKey) | Приватный ключ в чипе YubiKey | `age-plugin-yubikey`, ключ не извлекается |
| Директор (бюджет) | age-identity на USB-флешке | файл + passphrase |
| Полный доступ ×3 | YubiKey (обязательно) | `age-plugin-yubikey` + PIN + касание |

Приватный ключ **никогда** не покидает носитель и **никогда** не попадает на сервер.

## Мастер-доступ «2 из 3» (Shamir Secret Sharing)

Для опасных операций (выгрузка всей базы, смена корневого ключа, переназначение доступа ресторану) нужен мастер-секрет, разделённый на 3 части. Любые **2 из 3** восстанавливают его, **1 — нет**.

```
Мастер-секрет
   │  Shamir split (threshold = 2, shares = 3)
   ├── доля A → Полный доступ 1
   ├── доля B → Полный доступ 2
   └── доля C → Полный доступ 3

Восстановление: A+B, или A+C, или B+C  →  мастер-секрет
Одна доля в одиночку  →  бесполезна
```

- Инструмент: `ssss` (ssss-split / ssss-combine) или SLIP-0039.
- Каждая доля хранится на своём YubiKey/носителе своего владельца.
- Мастер-секрет собирается только в момент операции и сразу уничтожается из памяти.

## Смена и отзыв ключей
- **Потеря ключа директора:** двое из трёх переназначают ресторану новую пару ключей, перешифровывают конверты. Старый ключ отзывается.
- **Компрометация:** сменить DEK всех затронутых записей (перешифровать), пересобрать конверты без скомпрометированного ключа.
- **Ротация:** плановая смена корневых ключей раз в N месяцев.

## Алгоритмы (зафиксировано)
- Симметричное шифрование данных: **XChaCha20-Poly1305** (или AES-256-GCM).
- Обмен ключами / конверты: **X25519** (crypto_box / age).
- Хеш для audit-chain: **BLAKE2b** или SHA-256.
- KDF для passphrase: **Argon2id**.

## Важные правила
1. Открытый DEK и приватные ключи существуют только в оперативной памяти клиента, максимально коротко, затем затираются.
2. Сервер не участвует в расшифровке ни на одном шаге.
3. Никакой самописной криптографии — только libsodium/age.
