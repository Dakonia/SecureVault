# 01 · Архитектура

## Общая схема

```
┌─────────────────────────┐         ┌─────────────────────────┐
│  Компьютер директора     │         │  Компьютер с полным      │
│  (программа Tauri)       │         │  доступом (Tauri)        │
│                          │         │                          │
│  1. Ввод/загрузка данных │         │  Ключ на YubiKey         │
│  2. Шифрование локально  │         │  Открывает ВСЕ рестораны │
│     (libsodium/age)      │         │  Правки/комментарии      │
│  Ключ: YubiKey/флешка    │         │                          │
└───────────┬──────────────┘         └───────────┬──────────────┘
            │  только шифротекст                  │  только шифротекст
            │  (VPN WireGuard)                    │
            ▼                                     ▼
   ═══════════════ WireGuard (закрытый контур) ═══════════════
                              │
                    Single Packet Authorization
                    (порт открывается только своим)
                              │
            ┌─────────────────▼──────────────────┐
            │        ФИЗИЧЕСКИЙ СЕРВЕР            │
            │  Диск целиком: LUKS2 (шифрован)    │
            │  Unlock при ребуте: dropbear-ssh   │
            │                                    │
            │  API (Rust/Go) — только приём/     │
            │  выдача шифротекста, mTLS          │
            │  PostgreSQL — метаданные + blob    │
            │  MinIO/файлы — зашифрованные файлы │
            │  Audit-log — кто/что/когда         │
            │                                    │
            │  ❗ Открытых данных и ключей нет     │
            └────────────────────────────────────┘
                              │
                    Зашифрованный бэкап
                    (restic + age, ключ отдельно)
```

## Потоки данных

### Сдача отчёта (директор)
1. Директор вводит цифры или прикрепляет файл в программе.
2. Программа генерирует случайный ключ данных (DEK) и шифрует им содержимое (XChaCha20-Poly1305).
3. DEK кладётся в «конверт» под публичные ключи получателей (директор + 3 полных доступа).
4. Шифротекст + конверты уходят по WireGuard на сервер.
5. Сервер сохраняет всё как непрозрачные blob'ы. Расшифровать не может.

### Просмотр (полный доступ)
1. Человек вставляет YubiKey, вводит PIN.
2. Программа скачивает шифротекст и «свой конверт».
3. YubiKey расшифровывает конверт → достаётся DEK → расшифровываются данные локально.
4. Правки/комментарии шифруются заново и отправляются обратно.
5. Действие пишется в audit-log.

### Изоляция
Директор физически не имеет конверта от чужого ресторана → чужой DEK получить нечем → чужие данные для него навсегда «каша».

## Ключевые архитектурные решения
- **Клиент — толстый, сервер — тупой.** Вся криптография на клиенте. Сервер — «склад запертых коробок».
- **Нет публичной точки входа.** Ни домена, ни открытых портов. Только WireGuard + SPA.
- **Аналитика — компромисс.** См. [05-Роли-доступ-журнал.md](05-Роли-доступ-журнал.md): либо считать на клиенте админа после расшифровки, либо хранить отдельные согласованные агрегаты. Полноценная серверная аналитика противоречит zero-knowledge.
