# 08 · Чеклист безопасности (перед запуском)

## Главное правило (проверять постоянно)
- [ ] На сервере **нет** приватных ключей ни в каком виде.
- [ ] На сервере **нет** открытых (расшифрованных) данных — только blob.
- [ ] Сервер **не участвует** в расшифровке ни на одном шаге.

## Шифрование
- [ ] Данные шифруются на клиенте ДО отправки (XChaCha20-Poly1305 / AES-256).
- [ ] Конверты под получателей на X25519 (age/crypto_box).
- [ ] Используются только проверенные библиотеки (libsodium/age), не самопал.
- [ ] DEK и приватные ключи затираются из памяти сразу после использования.

## Ключи
- [ ] 3 человека с полным доступом — на YubiKey (не флешка, не пароль).
- [ ] Мастер-операции требуют «2 из 3» (Shamir), одна доля бесполезна.
- [ ] Каждый ключ защищён PIN/passphrase.
- [ ] Отработана процедура потери/отзыва ключа.
- [ ] Флешки-ключи (если у директоров) — с passphrase, не оставляются без присмотра.

## Сеть
- [ ] Нет публичного домена и публичного SSL-сертификата (Certificate Transparency).
- [ ] Доступ только через WireGuard.
- [ ] fwknop (SPA) включён, порт закрыт до секретного пакета.
- [ ] nftables policy = drop, наружу ничего не отвечает.
- [ ] mTLS: сервер отвечает только устройствам со своим сертификатом.

## Сервер
- [ ] Диск под LUKS2, ключ вводится удалённо (dropbear), не хранится на сервере.
- [ ] Открытые копии старых данных удалены (после перешифровки).
- [ ] Логи сервера не содержат чувствительных данных.

## Клиент (компьютеры)
- [ ] Программа не хранит открытых файлов/истории на диске.
- [ ] Диск компьютера зашифрован (BitLocker/FileVault).
- [ ] Отдельная учётка, автоблокировка.
- [ ] Нейтральное имя/иконка приложения.

## Журнал и контроль
- [ ] Audit-log append-only с hash-chain.
- [ ] Журнал регулярно выгружается в отдельное место.
- [ ] Водяные знаки на экранах/выгрузках.

## Бэкап
- [ ] Бэкапы зашифрованы (restic + age).
- [ ] Ключ бэкапа хранится ОТДЕЛЬНО от бэкапа и сервера.
- [ ] Восстановление протестировано на чистой машине.

## Юридическое
- [ ] Зарплаты/ФИО (персданные) — хранение в РФ (ФЗ-152).
- [ ] Зафиксировано: ключи у людей могут быть законно запрошены — принятый риск.
- [ ] Фото экрана — принятый риск, снижается водяными знаками.

## Проверка «от противного» (эмуляция захвата)
- [ ] Забрать образ выключенного сервера → данные нечитаемы (LUKS).
- [ ] Получить работающий сервер без клиентских ключей → данные нечитаемы (нет ключей).
- [ ] Директор пытается открыть чужой ресторан → «каша» (нет конверта).
- [ ] Один человек с полным доступом пытается мастер-операцию → блок (нужны двое).
