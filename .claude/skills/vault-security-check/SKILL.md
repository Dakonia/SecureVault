# Vault security check

Прогонять перед сдачей любого этапа SecureVault. Источник истины — `docs/08-Чеклист-безопасности.md` и `CLAUDE.md`. Сверять фактический код/конфиг, а не намерения.

## Красные флаги — искать в диффе
- Расшифровка или открытый DEK/приватный ключ где-либо в серверном коде.
- Отправка на сервер чего-либо, кроме шифротекста/конвертов/метаданных.
- Логирование открытых данных, ключей, passphrase.
- Ключ, записанный на диск сервера или в бэкап вместе с данными.
- Самописная крипта вместо age/libsodium; захардкоженные ключи/соли/nonce.
- Открытый порт, публичный домен/SSL-сертификат, обход WireGuard+SPA+mTLS.
- Audit-log без append-only / без hash-chain, либо запись, которую можно удалить.
- DEK/ключ, не затёртый из памяти после использования.

## Порядок
1. Определить, какой слой затронут (crypto-core / client / server / infra).
2. Прогнать блок чеклиста из `docs/08-Чеклист-безопасности.md` для этого слоя.
3. Проверить красные флаги выше по диффу.
4. Для крипто-изменений — «проверка от противного»: захват выключенного сервера, захват работающего без клиентских ключей, чужой директор, одиночная мастер-операция.
5. Вывести: PASS/FAIL по пунктам + конкретные файлы:строки с нарушениями.

Любое нарушение инвариантов 1–8 из `CLAUDE.md` — это FAIL, а не замечание.
